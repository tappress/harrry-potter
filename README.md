# Harry Potter Word Frequency Analyzer

## Пропозиції щодо оптимізації швидкодії (Time Optimization)

### 1. Використати lookup таблицю для перевірки літер
Замість умовних виразів `(ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z')` використати `boolean[] IS_LETTER = new boolean[256]`. Доступ до масиву O(1) швидший за обчислення умов.

### 2. Використати lookup таблицю для toLowerCase
Замість `Character.toLowerCase(ch)` використати попередньо обчислену таблицю `byte[] TO_LOWER = new byte[256]`. Уникає виклику методу та умовних перевірок.

### 3. Читати весь файл одним викликом Files.readAllBytes()
Для файлів < 10 MB читання всього файлу в пам'ять швидше ніж потокове читання через меншу кількість системних викликів.

### 4. Працювати напряму з byte[] замість String
Уникати створення проміжних String об'єктів. Обробляти байти напряму, створювати String тільки для фінального збереження в HashMap.

### 5. Використати побітову операцію для unsigned byte
`data[i] & 0xFF` замість кастингу для коректної роботи з байтами як unsigned значеннями.

### 6. Попередньо виділити HashMap з очікуваною ємністю
`new HashMap<>(15000)` замість дефолтного розміру. Уникає rehashing операцій при зростанні колекції.

### 7. Уникати String.split() та регулярних виразів
Регулярні вирази повільні. Пряма ітерація по байтах значно швидша.

### 8. Використати PriorityQueue (min-heap) для топ-K
Алгоритмічна складність O(n log k) замість O(n log n) для повного сортування. Для k=30 це суттєва різниця.

### 9. Ініціалізувати lookup таблиці в static блоці
Таблиці створюються один раз при завантаженні класу, а не при кожному виклику методу.

### 10. Використати int[] замість Integer/Long для лічильників
`Map<String, int[]>` уникає boxing/unboxing операцій. Інкремент `count[0]++` не створює нових об'єктів.

### 11. Мінімізувати кількість об'єктів в hot path
В циклі обробки тексту уникати створення нових об'єктів. Використовувати примітиви та переиспользовувати буфери.

### 12. Використати фіксований буфер для побудови слів
`byte[] wordBuffer = new byte[100]` замість StringBuilder. Прямий доступ до масиву швидший.

### 13. Уникати виклику методів в тісному циклі
Інлайнити прості операції замість виклику окремих методів для кожного символу.

### 14. Використати System.nanoTime() для точного вимірювання
`System.nanoTime()` має більшу точність ніж `LocalDateTime` для вимірювання коротких інтервалів.

### 15. Додати JVM warmup для benchmark
Перший запуск включає JIT компіляцію. Для точного вимірювання потрібні декілька прогрівальних ітерацій.

### 16. Використати -XX:+UseStringDeduplication для великих текстів
JVM прапор для дедуплікації однакових рядків в heap.

### 17. Застосувати computeIfAbsent для HashMap
`frequencies.computeIfAbsent(word, k -> new int[]{0})[0]++` - один lookup замість get + put.

### 18. Профілювати код з Java Flight Recorder
JFR дозволяє виявити bottlenecks та оптимізувати найповільніші частини.

### 19. Уникати автобоксингу в Comparator
`Comparator.comparingInt(e -> e.getValue()[0])` замість `Comparator.comparing()` з Integer.

### 20. Використати final для змінних в циклах
JIT може краще оптимізувати код з final змінними.

## Порівняння продуктивності

| Версія | Час виконання | Пам'ять |
|--------|---------------|---------|
| Оригінальна (O(n²)) | ~2000+ мс | Висока |
| Рефакторинг (Streams) | 108 мс | Середня |
| Memory Optimized | 39 мс | 73 KB |
| Time Optimized | 65 мс | 81 KB |

**Примітка**: Time Optimized версія оптимізована для швидкості при помірному використанні пам'яті.
Memory Optimized версія показує кращий час через streaming підхід, який уникає завантаження файлу повністю.
