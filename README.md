# Harry Potter Word Frequency Analyzer

Програма для аналізу частоти слів у тексті книги Harry Potter.

## Пропозиції щодо рефакторингу

### 1. Видалити невикористаний метод `cleanText()`
Метод `cleanText()` (рядки 16-20) визначений, але ніколи не використовується в методі `main()`. Замість цього логіка очищення тексту дублюється в `main()`.

### 2. Усунути дублювання коду
Логіка очищення тексту (`replaceAll` та `toLowerCase`) написана двічі - в методі `cleanText()` та в `main()`. Порушує принцип DRY.

### 3. Винести hardcoded шлях до файлу в константу
Шлях `"src/edu/pro/txt/harry.txt"` жорстко закодований у методі main(). Слід винести в константу або приймати як аргумент.

### 4. Замінити конкатенацію рядків на StringBuilder
Використання `+=` для конкатенації в циклі (рядок 38) має складність O(n²). StringBuilder значно ефективніший.

### 5. Використати HashSet для пошуку унікальних слів
Метод `distinctString.contains()` має складність O(n). HashSet забезпечує O(1) для перевірки наявності елемента.

### 6. Використати HashMap для підрахунку частоти
Вкладені цикли для підрахунку частоти (рядки 45-53) мають складність O(n²). HashMap дозволяє досягти O(n).

### 7. Покращити іменування змінних
- `distincts` → `distinctWords` або `uniqueWords`
- `freq` → `frequencies` або `wordFrequencies`
- `content` → `textContent` або `rawText`

### 8. Використати Java Streams API
Сучасні можливості Java 8+ дозволяють написати більш читабельний та ефективний код з використанням Stream API.

### 9. Винести магічне число 30 в константу
Число 30 (кількість топ-слів для виведення) жорстко закодоване без пояснення. Слід створити іменовану константу.

### 10. Розділити відповідальність (Single Responsibility Principle)
Весь код знаходиться в методі main(). Слід розділити на окремі методи:
- читання файлу
- очищення тексту
- підрахунок частоти
- сортування та виведення результатів

### 11. Обробляти виключення коректно
Метод main() просто пробрасує IOException. Слід обробляти виключення з інформативними повідомленнями.

### 12. Видалити закоментований код
Рядок 25 містить закоментований код `// Path path = Paths.get()`. Мертвий код слід видаляти.

### 13. Видалити невикористані імпорти
Імпорти `Collections` та `Collectors` не використовуються в коді.

### 14. Створити клас/record для слова з частотою
Замість зберігання частоти як частини рядка (`word + " " + count`), створити окремий клас або record `WordFrequency`.

### 15. Додати JavaDoc документацію
Методи та клас не мають документації. Слід додати JavaDoc для пояснення призначення.

### 16. Використати try-with-resources для читання файлу
Хоча `Files.readAllBytes()` автоматично закриває ресурси, для інших операцій варто використовувати try-with-resources.

### 17. Додати валідацію вхідних даних
Немає перевірки на:
- існування файлу
- порожній файл
- коректність шляху

### 18. Використати Path замість String для шляхів
Замість `String url` в методі `cleanText()` краще використовувати `Path`.

### 19. Додати можливість виводу в файл
Результати виводяться лише в консоль. Корисно додати опцію збереження у файл.

### 20. Використати final для незмінних змінних
Змінні, які не змінюються після ініціалізації, слід позначати як final.

### 21. Замінити цикл for на enhanced for-each
Де можливо, використовувати `for (String word : words)` замість індексованого циклу.

### 22. Використати Comparator.reverseOrder() для сортування
Замість доступу до масиву з кінця можна сортувати у зворотному порядку.

### 23. Додати підтримку Unicode та інших мов
Регулярний вираз `[^A-Za-z ]` працює лише з латиницею. Для підтримки інших мов використовувати `\p{L}`.

### 24. Винести логіку в окремі класи
Створити окремі класи:
- `TextReader` - для читання тексту
- `TextCleaner` - для очищення тексту
- `WordFrequencyAnalyzer` - для аналізу частоти
- `ResultPrinter` - для виведення результатів

### 25. Використати Optional для обробки null значень
Для безпечної роботи з потенційно null значеннями.

### 26. Оптимізувати регулярний вираз
Скомпілювати Pattern один раз замість використання String.replaceAll() кожного разу.
